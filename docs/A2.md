## 2. 상세

### A2-1. SQL 인젝션 — 공지 검색 `?q=` (A05)

- **대상**: `GET /notices/?q=` 공지 제목·내용 검색 (인증 불필요)
- **재현 절차**:
  1. 정상 대조: `?q=독감` → 공지 1건
  2. 참 조건 주입: `?q=' OR 1=1--` → 전체 공지 반환 (검색어가 SQL 조건으로 해석됨)
  3. UNION 주입으로 다른 테이블 유출 (제목 칸에 값을 실어 화면에 노출)
     ```
     GET /notices/?q=' UNION SELECT id,username||' = '||password,3,4,5 FROM auth_user--
     GET /notices/?q=' UNION SELECT id,name||' / '||guardian_tel,3,4,5 FROM center_child--
     ```
- **관찰된 응답(증거)**:
  ```
  admin = md5$btahXi3XVJZUIpjYOecfIo$16a1eefd5ec4cfd58248a33a0a64932e
  모의아동01 / 010-0000-2742
  모의아동03 / 010-0000-5531
  ... (sqlite_version() → 3.46.1 까지 추출)
  ```
  - 응답에 실린 비밀번호 해시가 MD5(솔트 포함) 형식이라 오프라인 크랙이 쉽습니다(사전 공격으로 `admin1234` 확인).
- **판단 근거(블랙박스)**: 작은따옴표를 넣은 검색어가 오류 없이 처리되고, `UNION SELECT`로 테이블명을 지정했을 때 해당 테이블 값이 결과에 나타남 → 검색 파라미터가 SQL 문법으로 실행됨.
- **영향도**: Critical — 인증 없이 전체 DB 열람. 아동·보호자 PII, 관리자 자격증명 유출.
  CVSS 3.1 ≈ 9.1 `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:L/A:N`
- **권고 조치**: 검색어를 쿼리에 문자열로 결합하지 말고 파라미터 바인딩/ORM 질의로 처리. 입력 검증은 보조 수단으로만.
- **PoC**: `a05_sqli.sh`, `a05_sqli2.sh`

### A2-2. 저장형 XSS — 게시글·댓글 (A05)

- **대상**: `/board/posts/` 글·댓글 작성·열람 (로그인 필요 — `/signup/`으로 계정 생성)
- **재현 절차**:
  1. 글 본문에 `<script>alert(document.cookie)</script>` 입력 후 저장
  2. 댓글 본문에 `<img src=x onerror=alert(1)>` 입력 후 저장
  3. 글 상세를 다시 요청
- **관찰된 응답(증거)**: 응답 HTML 에 payload 가 **이스케이프 없이** 그대로 포함됨(`&lt;script&gt;`가 아니라 `<script>` 그대로). 브라우저로 열면 실제 실행됨.
- **판단 근거(블랙박스)**: 입력한 태그가 응답에서 엔티티 치환 없이 원문으로 반환됨 → 저장형 XSS.
- **영향도**: High — 저장형이라 그 글을 여는 모든 사용자(직원 포함)에게 실행. `sessionid`는 HttpOnly 라 직접 탈취는 막히나(응답 쿠키 속성에서 확인), 읽히는 `csrftoken`·`role` 쿠키 탈취·요청 위조·화면 변조가 가능.
  CVSS 3.1 ≈ 8.0 `AV:N/AC:L/PR:L/UI:R/S:C/C:H/I:L/A:N`
- **권고 조치**: 사용자 입력을 HTML 로 출력할 때 자동 이스케이프 적용. 서식이 꼭 필요하면 허용목록 기반 정제. 응답에 CSP 헤더 추가.
- **PoC**: `a05_xss.sh`

### A2-3. 게시글 IDOR — 수정·삭제 (A01)

- **대상**: `POST /board/posts/<id>/edit/`, `/board/posts/<id>/delete/`
- **재현 절차**: alice 계정으로 글 2건 작성 → bob 계정으로 로그인해 alice 글을 수정·삭제 요청.
- **관찰된 응답(증거)**:
  ```
  bob 이 수정한 글의 현재 제목: BOB 이 수정함(변조)
  bob 이 삭제한 글 재조회: HTTP 404 (삭제됨)
  ```
- **판단 근거(블랙박스)**: 작성자가 아닌 계정의 수정·삭제 요청이 성공(변경 반영, 404) → 객체 수준 접근 통제 부재.
- **영향도**: High — 로그인한 누구나 타인 게시물 변조·삭제.
  CVSS 3.1 ≈ 8.1 `AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:H/A:H`
- **권고 조치**: 수정·삭제 시 요청자가 글 작성자(또는 직원)인지 서버에서 확인하고, 아니면 403.
- **PoC**: `a01.sh`

### A2-4. 남의 아이 출결 조회 IDOR (A01)

- **대상**: `GET /my/?child=<id>` (및 `GET /my/<id>/`)
- **재현 절차**: bob(어떤 아동의 보호자도 아님)으로 로그인 후 `?child=1,2,3`으로 조회.
- **관찰된 응답(증거)**:
  ```
  ?child=1 -> 모의아동01
  ?child=2 -> 모의아동02
  ?child=3 -> 모의아동03
  ```
  (아동 이름·입퇴실·사유가 노출. 쓰기는 없음)
- **판단 근거(블랙박스)**: 보호자-아동 소속과 무관하게 `child` 값만 바꾸면 타 아동 데이터가 반환됨 → 객체 수준 접근 통제 부재.
- **영향도**: Medium — 타 아동 PII 열람.
  CVSS 3.1 ≈ 6.5 `AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N`
- **권고 조치**: 조회를 요청자 소속 아동으로 제한하고, `child` 지정 시 소유 여부를 서버에서 확인.
- **PoC**: `a01.sh`

### A2-5. SSRF — 외부 임베드 (A01)

- **대상**: `GET /embed/?url=` (서버가 URL 을 가져와 앞부분을 보여줌)
- **재현 절차**:
  ```
  GET /embed/?url=file:///etc/passwd
  ```
- **관찰된 응답(증거)**: 미리보기에 `root:x:0:0:root:/root:/bin/bash ...` 노출(서버의 로컬 파일을 읽어 반환).
- **판단 근거(블랙박스)**: 임의 스킴(`file://`)의 URL 을 서버가 받아 그 내용을 응답에 담음 → 서버 측 요청 위조. 같은 방식으로 내부망·클라우드 메타데이터(`http://169.254.169.254/`)·서버 설정 파일에 닿을 수 있음.
- **영향도**: High — 로컬 파일 유출·내부망 탐색. 설정/시크릿 유출 시 세션 위조로 확대 가능.
  CVSS 3.1 ≈ 8.6 `AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:N/A:N`
- **권고 조치**: 스킴을 `http/https`로 제한(`file/ftp/gopher` 차단), 대상 호스트 허용목록, 사설·루프백·링크로컬 IP 차단, 리다이렉트 비허용, 타임아웃 유지. 불필요하면 기능 제거.
- **PoC**: `a01.sh`

## 3. 검증

- 전 항목을 격리 환경 `127.0.0.1:8000`에서 curl 로 재현하고 요청·응답을 스크립트로 저장했습니다.
- SQLi: 정상 검색(`q=독감` 1건) 대비 `OR 1=1`(전체)·UNION(타 테이블) 응답 차이로 확인.
- XSS: 응답 바이트에 `<script>`가 이스케이프 없이 존재함을 확인.
- IDOR: 작성자/보호자가 아닌 세션의 요청 성공(제목 변경·404·타 아동 반환)으로 확인.
- SSRF: `/etc/passwd` 첫 줄(`root:...`) 노출로 확인.
