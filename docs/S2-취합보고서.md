## 1. 종합 요약

담당 5개 항목을 블랙박스(ZAP·수동) → 화이트박스(소스) 순으로 진단했다. 4개 항목에서 취약점을 확인했고, 1개(A03)는 취약점이 없음을 확인했다. 취약점 미발견도 유효한 진단 결과로 기록한다.

| 항목 | 취약점 | 위험도 | 상태 |
| --- | --- | --- | --- |
| A10 예외 처리 | DEBUG 모드 ON — 상세 오류 페이지 노출 | High | 조치 전 |
| A02 보안 설정 | 약한 기본 관리자 계정 | High | 조치 전 |
| A02 보안 설정 | 서버 버전 노출·CSP 헤더 없음 | Low~Medium | 조치 전 |
| A04 암호화 | 비밀번호 MD5 저장 | High | 조치 전 |
| A04 암호화 | 쿠키 Secure 누락·HTTP 평문 전송 | Medium | 조치 전 |
| A09 보안 로깅 | 로그인 실패·CSV 열람 미기록 | Medium | 조치 전 |
| A03 공급망 | (의존성 스캔) | — | 취약점 없음 |

- 위험도는 팀 공식 산정 전 참고치.
- "조치 전"은 W9 `secure` 브랜치 반영 후 B5에서 재검증 예정을 뜻한다.

## 3. 항목별 상세

### A10 — 예외 처리: DEBUG 모드 상세 오류 노출 (High)

- **발견(B2):** 정수 PK 자리에 문자를 넣어 오류 유발 시(`GET /notices/abc/`) Django 디버그 페이지가 반환됨. `Request Method`, `Request URL`, `Using the URLconf`(URL 패턴 전체), 설정 모듈 경로 노출.
- **근본 원인(B4):** `config/settings.py:32`
  ```python
  DEBUG = os.environ.get('DJANGO_DEBUG', '1') == '1'
  ```
  기본값이 `'1'`이고 compose도 `DJANGO_DEBUG=1`로 기동.
- **영향도:** 운영 시 URL 구조·설정·소스 조각 노출. CVSS 참고치 5.3.
- **권고:** 운영 `DJANGO_DEBUG=0`, 커스텀 404/500 템플릿.
- **재현:** `curl -s http://127.0.0.1:8000/notices/abc/`
- **비고:** ZAP 자동 스캔은 404를 오류로 보지 않아 놓침 → 수동 확인.

### A02 — 보안 설정: 약한 기본 관리자 계정 (High)

- **발견(B2):** 흔한 조합 점검 중 `admin` / `admin1234` 로그인 성공(무차별 대입 아님, 기본값 점검).
- **근본 원인(B4):** `center/management/commands/seed_dummy.py:53-54`
  ```python
  User.objects.filter(username='admin').exists() or \
      User.objects.create_superuser('admin', 'admin@example.com', 'admin1234')
  ```
- **영향도:** 관리자 권한 탈취로 직결.
- **권고:** 기본·약한 계정 제거, 강한 비밀번호 정책.

### A02 — 보안 설정: 정보 노출 (Low~Medium)

- **발견(B2):** `Server: WSGIServer/0.2 CPython/3.14.10`(버전 노출), CSP 헤더 없음(ZAP 능동 스캔 Medium).
- **참고:** `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `COOP`는 설정됨 — 전부 취약하지 않음.
- **권고:** 서버 버전 숨김, CSP 추가.

### A04 — 암호화: 비밀번호 MD5 저장 (High)

- **발견(B2→B4):** B2에서는 응답으로 확인 불가해 보류, B4 소스에서 확정.
- **근본 원인(B4):** `config/settings.py:27`
  ```python
  PASSWORD_HASHERS = ['django.contrib.auth.hashers.MD5PasswordHasher']
  ```
- **교차 입증(B4):** S1의 A05(SQL 인젝션)로 유출된 관리자 해시가 `md5$...` 형식 → MD5 저장 확인. 오프라인 크랙으로 `admin1234` 복원(S1).
- **영향도:** DB 유출 시 비밀번호 즉시 크랙. CVSS 참고치 High.
- **권고:** PBKDF2/argon2 등 느린 해시로 교체.

### A04 — 암호화: 쿠키 Secure 누락·HTTP 평문 (Medium)

- **발견(B2):** 전송이 HTTP 평문. 쿠키 플래그가 쿠키별로 다름.

  | 쿠키 | HttpOnly | Secure |
  | --- | --- | --- |
  | `sessionid` | 있음 | 없음 |
  | `csrftoken` | 없음 | 없음 |

- **근본 원인(B4):** `config/settings.py:184-187`
  ```python
  if not DEBUG:
      SECURE_SSL_REDIRECT = True
      SESSION_COOKIE_SECURE = True
      CSRF_COOKIE_SECURE = True
  ```
  보호 설정이 `if not DEBUG` 블록에만 있어 DEBUG=1인 현재 미적용.
- **영향도:** 평문 구간 탈취, `csrftoken`은 JS 접근도 가능.
- **권고:** HTTPS 강제(HSTS), 모든 쿠키 `Secure`, `csrftoken`에 `HttpOnly`.

### A09 — 보안 로깅: 실패·민감조회 미기록 (Medium)

- **발견(B3):** 로그 동작 관찰 결과

  | 이벤트 | 기록 |
  | --- | --- |
  | 로그인 성공 | 기록됨 (`security.log`에 `login_ok ip= user_id=`) |
  | 로그인 실패 | **미기록** |
  | CSV 열람(`/attendance/export/`) | **미기록** |
  | CSRF 거부·500 | 기록됨 (`error.log`, 프레임워크 기본) |

- **근본 원인(B4):** `center/views.py:122-126` (`limited_login`)
  ```python
  if response.status_code == 200:      # 실패하면 폼이 다시 그려져 200
      pass                             # ← 기록도 카운트도 없음
  else:
      security_log.info('login_ok ...')   # 성공만 기록
  ```
  잠금 함수 `_blocked()`(`views.py:100`)·`_count_failure()`(`views.py:104`)가 정의만 되고 호출 안 됨.
- **교차 연계:** 실패가 기록도 안 되고 잠기지도 않아, S1 A07(로그인 무제한 시도)과 같은 코드가 원인. 무차별 대입 탐지 불가.
- **영향도:** 공격 탐지·사후 추적 불가. CVSS 참고치 5.3.
- **권고:** 실패 분기에 `security_log` 기록 + 실패 카운트·잠금 실제 호출, 민감 데이터 열람 감사 로그.

### A03 — 공급망: 의존성 (취약점 없음)

- **진단(B3):** `lab/vuln_practice_web_v1/requirements.txt` 대상 `pip-audit`.
  - `Django==6.1.3`, `asgiref==3.13.0`, `sqlparse==0.6.1` (컨테이너 설치 버전과 일치)
- **결과:** No known vulnerabilities found. 구버전·CVE 라이브러리 없음.
- **해석:** 현재 앱에 A03 취약점은 구현되지 않음. 조치 필요 소견 없음.

## 4. 진행 방식·원칙

- **블랙박스 우선:** 2단계 진단 중 취약판 소스를 열지 않고 스캐너·수동 재현으로 탐지. 3단계부터 소스 분석(화이트박스). 의존성 목록은 스캔 입력이라 예외.
- **안전 범위 통제:** 능동 스캔은 W가 전달한 제외 경로(로그아웃·계정 생성·데이터 삭제·외부 요청) 밖만 공격.
- **자동 + 수동 병행:** ZAP이 놓친 항목(DEBUG·로깅)을 수동으로 보완, 자동 판정을 수동으로 재확인.
- **교차검증:** S1 A05(SQLi)를 1건 재현, A04(MD5 저장)와 맞물림 확인.

## 5. 남은 것

- **B5 조치 재검증:** W9 `secure` 브랜치가 올라오면 위 근본 원인별로 조치 확인(디버그 미노출, 기본 계정 제거, 해시 교체, 쿠키 Secure 적용, 실패 로깅·잠금). 같은 스크립트로 재스캔·재현 비교.
- **W8 대조:** 답지 성격이라 전 진단 종료 후 "내가 찾은 것 vs W가 심은 것" 커버리지 검증으로 수행.
- **로그인 스캔 보강:** 비로그인 ZAP 스캔이라, 로그인 이후 화면은 세션 주입 스캔으로 추가 가능(선택).
