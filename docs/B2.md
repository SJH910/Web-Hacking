## 2. 상세

### A10 — DEBUG 모드 상세 오류 노출 (High)

- 대상: 전역(오류를 유발하는 모든 경로). 재현은 `GET /notices/abc/`
- 재현: 정수 PK 자리에 문자열을 넣어 404를 유발하면 Django 디버그 페이지가 반환됨
- 노출 정보: `Request Method`, `Request URL`, `Using the URLconf ...`(URL 패턴 전체), 설정 모듈 경로
- 영향도: 운영 환경이라면 URL 구조·설정·소스 조각이 공격자에게 노출. CVSS 참고치 5.3(정보 노출, AV:N/AC:L/PR:N/UI:N/C:L)
- 권고: 운영에서 `DEBUG=False`, 커스텀 404/500 템플릿 사용
- PoC: `curl -s http://127.0.0.1:8000/notices/abc/ -o debug.html` → 디버그 페이지 확인
- 비고: ZAP 자동 스캔은 404를 오류로 보지 않아 놓쳤고, 수동으로 확인함

### A04 — 전송·저장 보호 미흡 (Medium)

- 대상: 로그인·세션 전반
- 발견(쿠키 플래그는 쿠키별로 다름 — 2026-11-13 로그인 응답까지 확인해 정정):

  | 쿠키 | `HttpOnly` | `Secure` | 기타 |
  | --- | --- | --- | --- |
  | `sessionid` | 있음 | **없음** | 로그인 응답에서 확인 |
  | `csrftoken` | **없음** | **없음** | `SameSite=Lax` |

  - `sessionid`는 `HttpOnly`가 걸려 JS 접근은 막히나, `Secure`가 없어 평문 구간에서 샐 수 있음
  - `csrftoken`은 `HttpOnly`·`Secure` 모두 없음
  - 서비스가 HTTP로만 열려 로그인 자격증명·쿠키가 평문 전송
- 영향도: 평문 구간 탈취, `csrftoken`은 JS를 통한 접근도 가능
- 권고: HTTPS 강제(HSTS), 모든 쿠키에 `Secure`, `csrftoken`에 `HttpOnly`, `SESSION_COOKIE_SECURE`/`CSRF_COOKIE_SECURE=True`
- PoC: 로그인 POST 응답 헤더 (쿠키 값은 세션 노출 방지를 위해 마스킹)

  ```text
  # 재현: 로그인 POST  http://127.0.0.1:8000/login/   ← 전체가 http, HTTPS 아님  [A04 평문 전송]
  HTTP/1.1 302 Found
  Location: /my/                                   # 로그인 성공(302). 실패면 200(페이지 재표시)
  Server: WSGIServer/0.2 CPython/3.14.10           # [A02] 서버·파이썬 버전 노출
                                                   # [A02] CSP 헤더 없음(있어야 할 헤더 누락)
  Cache-Control: ...no-store...                    # 양호(로그인 페이지 캐시 금지)
  X-Frame-Options: DENY                            # 양호
  X-Content-Type-Options: nosniff                  # 양호
  Referrer-Policy: same-origin                     # 양호
  Set-Cookie: csrftoken=<값 생략>; Max-Age=31449600; Path=/; SameSite=Lax
                                                   # [A04] csrftoken: HttpOnly X / Secure X
  Set-Cookie: sessionid=<값 생략>; HttpOnly; Path=/; SameSite=Lax
                                                   # [A04] sessionid: HttpOnly O / Secure X
  ```

  재현 명령:
  ```bash
  J=$(mktemp)
  T=$(curl -s -c $J "$B/login/" | grep -oE 'name="csrfmiddlewaretoken" value="[^"]+"' | sed -E 's/.*value="([^"]+)"/\1/')
  curl -s -D - -o /dev/null -b $J -e "$B/login/" \
    -d "csrfmiddlewaretoken=$T&username=admin&password=admin1234" "$B/login/"
  ```
- 남은 것: 비밀번호 **저장** 방식(해시 알고리즘)은 응답으로 확인 불가. 화이트박스(B4)에서 확인

### A02 — 약한 관리자 계정 (High)

- 대상: 로그인(`/login/`)
- 발견: 흔한 자격증명 점검 중 `admin` / `admin1234`로 로그인 성공
- 방법: 무차별 대입이 아니라 기본·약한 조합 8개 점검. 그중 1개 적중(이 자체가 A02 소견)
- 영향도: 관리자 권한 탈취로 이어짐. 전형적인 보안 설정 미흡
- 권고: 기본·약한 계정 제거, 강한 비밀번호 정책, 관리자 접근 제한
- PoC: `POST /login/`에 `username=admin&password=admin1234` → 302 + `sessionid` 발급
- 비고: 2026-11-13 B3 진단 중 유효 세션 확보 과정에서 확인

### A02 — 설정·정보 노출 (Low~Medium)

- 발견:
  - `Server: WSGIServer/0.2 CPython/3.14.10` — 서버 종류·파이썬 버전 노출
  - CSP 헤더 없음 (ZAP 능동 스캔 Medium, 3건)
  - 능동 스캔 기타: `X-Content-Type-Options` 일부 누락, 비저장 콘텐츠 등
- 참고: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `COOP`는 설정돼 있음 — 전부 취약하지는 않음
- 권고: 서버 버전 숨김, CSP 추가
- PoC: `curl -s -D - -o /dev/null http://127.0.0.1:8000/`
