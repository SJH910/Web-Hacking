# [B1] ZAP 환경 구축 — 일부 완료

- 담당: S2
- 완료일: 2026-11-06
- 상태: ZAP·DVWA 환경과 자동 스캔 연습 완료. **의존성 스캐너는 C1(기술 스택 결정) 후 선택**
- 관련 이슈·커밋: 없음

## 1. 결과 요약

로컬 Docker에 DVWA와 ZAP 2.17.0을 구성하고, 기본 스캔과 로그인 세션을 쓴 능동 스캔을 모두 실행했습니다. 능동 스캔은 DVWA의 SQL Injection과 XSS를 탐지했습니다. 실행 방법은 `lab/README.md`에 있습니다.

| 구성 | 값 |
| --- | --- |
| DVWA | `ghcr.io/digininja/dvwa:latest`, `127.0.0.1:4280` 바인딩 |
| DB | `mariadb:10` |
| ZAP | `ghcr.io/zaproxy/zaproxy:stable` (2.17.0) |

## 2. 상세

### 기본 스캔

- 대상: `http://dvwa/` (로그인 없음)
- 결과: 경고 13종, 통과 55종, 실패 0종
- 로그인 페이지까지만 보이므로 내부 기능은 진단하지 못합니다.

### 능동 스캔

- 대상: `sqli`, `xss_r` 페이지, security=low, admin 세션
- 소요 시간: 약 2분 39초

| 위험도 | 항목 | 비고 |
| --- | --- | --- |
| High | SQL Injection - MySQL | `sqli`의 `id` 파라미터 |
| High | Cross Site Scripting (Reflected) | `xss_r`의 `name` 파라미터 |
| High | Cross Site Scripting (DOM Based) | `xss_r` |
| High | PHP Version with Known Vulnerabilities | 버전 기반 판정 |
| Medium | CSP 헤더 없음, HTTP 전용 사이트, 클릭재킹 방지 헤더 없음, Parameter Tampering | Parameter Tampering은 신뢰도 Low |
| Low | `X-Powered-By`·`Server` 버전 노출, `X-Content-Type-Options` 없음 | |

탐지 결과는 자동 판정이며, 항목별 수동 재현은 하지 않았습니다. SQL 오류 응답만 curl로 확인했습니다.

## 3. 검증

- 포트 확인: `127.0.0.1:4280`으로만 수신 중
- 로그인 확인: `admin` 로그인 후 `index.php` 접근 성공
- 스캔 유효성 확인: 첫 능동 스캔은 성공으로 끝났지만 SQLi·XSS가 0건이었습니다. 같은 쿠키로 curl을 보내면 SQL 오류가 나왔고, ZAP 요청에는 세션이 실리지 않았습니다. `replacer` 작업을 `ZAP_AUTH_HEADER`로 바꾼 뒤 다시 실행해 탐지를 확인했습니다.

## 4. 남은 것·참고

- 의존성 스캐너: C1 후 선택합니다. Node면 `npm audit`(설치됨), Python이면 `pip-audit`(미설치), Java면 OWASP Dependency-Check.
- B2 적용: 스캔이 성공으로 끝나도 알려진 취약 지점이 탐지되는지 먼저 확인합니다.
- B2 전까지 필요한 것: W의 웹앱 로그인 방식(세션 쿠키 또는 토큰), 스캔 제외 경로(로그아웃, 데이터 초기화 등)
- DVWA 이미지는 `latest` 태그라 시점에 따라 결과가 달라질 수 있습니다. 재현이 중요해지면 digest로 고정합니다.
