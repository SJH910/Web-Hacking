## 2. 상세

### A3-1. 약한 전화 인증번호 (A06)

- **대상**: `POST /signup/phone/` 전화번호 인증 가입
- **재현 절차**:
  1. 전화번호만 전송(인증번호 요청)
  2. 응답에 표시된 번호로 재전송(가입 완료)
- **관찰된 응답(증거)**:
  ```
  응답 안내문: "인증번호 122 를 보냈습니다"   ← 번호가 응답에 그대로 노출
  재전송 결과: "가입이 완료되었습니다"
  ```
  - 여러 번 반복하면 번호는 항상 3자리(100~999, 경우의 수 900)였고, 틀린 번호를 반복 입력해도 막히지 않았습니다.
- **판단 근거(블랙박스)**: 인증번호가 응답 본문에 노출되고, 자릿수가 작으며, 시도 제한·만료가 관찰되지 않음.
- **영향도**: High — 임의 전화번호로 계정 생성·가로채기.
  CVSS 3.1 ≈ 7.5 `AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:H/A:N`
- **권고 조치**: 충분히 긴(6자리+) 난수 인증번호를 안전한 난수원으로 생성, **응답에 번호 미포함**(실제 SMS 로만), 만료 시간 + 시도 횟수 제한, 성공 시 코드 폐기.
- **PoC**: `a0607.sh`

### A3-2. 로그인 시도 제한 없음 (A07)

- **대상**: `POST /login/`, `POST /admin/login/`
- **재현 절차**: `admin` 계정에 틀린 비밀번호 20회 연속 전송 → 직후 올바른 비밀번호 전송.
- **관찰된 응답(증거)**:
  ```
  시도 1..20 -> HTTP 200   (잠금·429·차단 메시지 없음)
  올바른 비밀번호 -> HTTP 302   (로그인 성공)
  ```
- **판단 근거(블랙박스)**: 연속 실패 후에도 계정/소스 IP 가 잠기지 않고 올바른 자격증명이 바로 통과 → 시도 제한 부재.
- **영향도**: High — 자격증명 전수 대입으로 계정(관리자 포함) 탈취.
  CVSS 3.1 ≈ 8.1 `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:L/A:N`
- **권고 조치**: 로그인 실패를 (소스 IP, 아이디) 기준으로 집계해 임계 초과 시 일시 차단, IP 전체 한도 병행. 공유 캐시·실제 클라이언트 IP 식별 전제. 가능하면 2차 인증 도입.
- **PoC**: `a0607.sh`

### A3-3. 쿠키 `role=staff` 위조 — 권한 상승 (A08)

- **대상**: `GET /attendance/board/` 직원용 현황판
- **재현 절차**: 일반 사용자(비직원)로 로그인 후
  1. 쿠키 없이 접근
  2. 요청에 쿠키 `role=staff` 추가 후 접근
- **관찰된 응답(증거)**:
  ```
  쿠키 없음 -> HTTP 302 (관리자 로그인으로 리다이렉트)
  role=staff -> HTTP 200 (현황판 열림)
  ```
- **판단 근거(블랙박스)**: 서버가 서명·검증하지 않는 평문 쿠키 값(`role=staff`)만으로 직원 전용 화면 접근을 허용 → 클라이언트 신뢰에 의한 권한 상승.
- **영향도**: High — 비직원이 전체 아동 출결 조회·수정(정산 근거 위조).
  CVSS 3.1 ≈ 8.1 `AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:N`
- **권고 조치**: 권한 판정을 서버 측 세션/계정 속성으로만 수행하고, 클라이언트가 보낸 역할 쿠키는 신뢰하지 않음. 신뢰가 필요한 쿠키는 서명·암호화.
- **PoC**: `a08.sh`

### A3-4. 무검증 파일 업로드 (A08)

- **대상**: `POST /my/` 서류 업로드(`doc`)
- **재현 절차**: `.php` 내용 파일을 가짜 MIME(`image/png`)로 업로드.
- **관찰된 응답(증거)**: 거부 없이 업로드가 수락되고, 저장 경로가 `docs/webshell.php`(원래 이름·확장자 유지)로 응답에 나타남.
- **판단 근거(블랙박스)**: 실행형 확장자·불일치 MIME 가 형식 검사 없이 수락됨 → 업로드 형식 제한 부재. (현재 구성에서는 업로드 파일이 HTTP 로 바로 열리지 않아 즉시 실행은 확인되지 않음.)
- **영향도**: Medium(현재 구성) — 다만 업로드 경로가 서빙되거나 노출되면 저장형 XSS/웹셸(RCE)로 상승.
  CVSS 3.1 ≈ 6.5 `AV:N/AC:L/PR:L/UI:N/S:U/C:L/I:H/A:N` (서빙 구성에선 Critical)
- **권고 조치**: 파일 내용(매직바이트) 기반 형식 판정 + 확장자 허용목록 + 크기 제한, 저장 이름 난수화, 웹루트 밖 저장, 실행 불가 응답(`Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`). 공지 첨부 다운로드는 이미 올바르게 처리되므로 그 방식을 기준으로 삼으면 됩니다.
- **PoC**: `a08.sh`
