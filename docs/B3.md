## 2. 상세

### A03 — 소프트웨어 공급망 (취약점 없음)

- 대상: `lab/vuln_practice_web_v1/requirements.txt`
  - `Django==6.1.3`, `asgiref==3.13.0`, `sqlparse==0.6.1`
- 방법: `pip-audit 2.10.1`로 스캔. 컨테이너 설치 버전(`pip freeze`)과 `requirements.txt`가 일치함을 먼저 확인
- 결과: **No known vulnerabilities found**
- 해석: 취약판에 구버전·CVE 라이브러리가 들어가 있지 않다. PLAN.md의 A03(구버전 라이브러리)은 현재 앱에 구현되지 않은 상태. 조치가 필요한 소견은 없음
- PoC: `.venv/bin/pip-audit -r vuln_practice_web_v1/requirements.txt`

### A09 — 보안 로깅 및 경보 (취약점 존재)

- 대상: 인증 이벤트, 민감 데이터 열람
- 로그 구조: 컨테이너 `/app/logs/`에 `error.log`(프레임워크), `security.log`(앱 보안 채널)

| 이벤트 | 기록 여부 | 근거 |
| --- | --- | --- |
| 로그인 성공 | 기록됨 | `security.log`에 `INFO center.security login_ok ip=... user_id=...` |
| 로그인 실패 | **미기록** | 실패 시도 8건이 `security.log`·`error.log` 어디에도 없음 |
| CSV 열람(`/attendance/export/`) | **미기록** | 200 CSV 반환됐으나 로그 라인 없음 |
| CSRF 거부·서버 500 | 기록됨 | `error.log`에 `django.security.csrf`, `django.request` |

- **핵심 취약점:** 로그인 **실패가 전혀 기록되지 않는다.** 무차별 대입·크리덴셜 스터핑의 신호가 남지 않아 공격 탐지가 불가능하다. 성공은 IP·user_id까지 남기는 것과 대비된다.
- 영향도: 공격 탐지·사후 추적 불가. CVSS 참고치 5.3(정보성, 탐지 실패)
- 권고: 인증 실패를 `security.log`에 기록(사용자명·IP·시각), 실패 임계치 경보, 민감 데이터(CSV) 열람 감사 로그 추가
- PoC(재현):
  1. `security.log` 크기 확인
  2. 틀린 비밀번호로 `POST /login/` → 응답 200(재표시), 로그 변화 없음
  3. 올바른 계정으로 로그인 → `login_ok` 한 줄 추가
  4. `GET /attendance/export/` → CSV 200, 로그 변화 없음
- 비고: C3에서 W는 "로그인·CSV 열람 로그가 있다"고 했으나, 런타임 관찰에서는 로그인 성공만 기록되고 실패·CSV 열람은 기록되지 않았다. 관리자 화면의 다른 CSV 경로 로깅 여부는 B4에서 교차 확인

## 3. 검증

- 포트: `127.0.0.1:8000`, ZAP/스캔은 compose 네트워크 `jiacenter-vuln_lab`
- A03: `pip-audit` 재실행 일관됨. `requirements.txt` == 컨테이너 설치 버전
- A09: 로그인 실패→성공→CSV 열람 순으로 유발하며 `security.log` 변화를 매 단계 관찰
- 로그 파일 직접 확인: `docker exec jiacenter-vuln-web-1 cat /app/logs/security.log`
- 유효 계정은 A02 기본·약한 계정 점검에서 확보(`admin`/`admin1234`). 무차별 대입 아님(흔한 조합 8개 점검 중 1개 적중)

## 4. 남은 것·참고

- **관리자 CSV 로깅:** 로그인 필요한 관리자 화면의 CSV 경로 로깅 여부는 미확인. B4 화이트박스에서 확인
- **A02·A04로 넘길 소견(B2 보고서에 반영):**
  - A02: 약한 관리자 계정(`admin`/`admin1234`) 로그인 성공 — 기본·약한 자격증명
  - A04 정정: 쿠키 플래그가 쿠키별로 다름. `sessionid`는 `HttpOnly` 있음/`Secure` 없음, `csrftoken`은 `HttpOnly` 없음. B2.md의 "쿠키 HttpOnly 없음" 표현을 이 내용으로 정정
- **부수 관찰(제 항목 아님, S1 전달용):** `error.log`에 SSRF 탐침 흔적(`DisallowedHost: ...169.254.169.254` 클라우드 메타데이터 IP)과 `php://input`/`auto_prepend_file` 페이로드. 누군가 `/embed`·`/login`에 공격을 시도한 기록. A01(SSRF)·주입 계열은 S1 담당
- **블랙박스 유지:** 취약판 소스(`center/`, `config/`)는 진단 중 열지 않음. `requirements.txt`는 A03 스캔 입력이라 예외
