## 1. 결과 요약

웹앱(지역아동센터 홈페이지)을 두 환경(집 Windows → 강의장 Mac)에서 나눠 작업하면서 계보가 둘로 갈라졌고, 이번에 하나로 합쳤습니다. 그 과정에서 PLAN.md 가 정한 10개 항목 중 8개는 심었고, 2개(W2 비밀번호 재설정, W3 게시글 수정 IDOR 중 후자)는 애초 계획에서 빠져 있던 것을 확인해 하나(게시글 수정·삭제 IDOR)는 이번에 새로 채웠습니다.

## 2. 상세

### 왜 계보가 갈라졌나

작업 중간에 평소 쓰던 환경(강의장 Mac)을 쓸 수 없는 사정이 생겨, 집 Windows 환경에서 급하게 작업을 이어갔습니다. Windows 에는 Docker 가 없어 만든 기능을 실제로 띄워 보지 못한 채로 커밋했습니다. 이후 Mac 환경으로 돌아와 두 작업물을 하나로 합쳤습니다.

같은 지시(OWASP Top 10 에 맞춰 취약점 심기)를 받고도, 두 환경에서 만든 결과물은 서로 다른 6개씩을 골라 심었습니다. 합치면서 겹치는 항목(공지 검색 SQL 삽입, 공지 서식 XSS)은 하나만 남기고, 나머지는 모두 살렸습니다.

## 3. 검증

- Django 테스트 94개 통과(3개 건너뜀). 새로 추가한 게시글 수정·삭제 IDOR 은 "다른 사람이 로그인만 하고 남의 글을 고치고 지울 수 있는지" 확인하는 테스트로 직접 확인했습니다.
- 실습본에서 내부 문서·공격 설명을 뺀 사본을 만드는 스크립트를 실제로 돌려 통과시켰고, `manage.py check`, 공개 전 자료가 남지 않았는지 재검사도 통과했습니다.
- `docker compose up --build` 로 Mac 에서 직접 띄워 `/`, `/signup/`, `/signup/phone/`, `/board/posts/` 등 주요 화면과 공지 검색 SQL 삽입, 전화 인증번호 노출을 확인했습니다.

## 4. 남은 것·참고

- **A09(로그 없음)이 실제로는 안 심어져 있을 수 있습니다.** 내부 `vuln-manifest.md` 에는 "main 에도 로그가 없어서 심지 않았다"고 적혀 있었는데, main 코드를 직접 보니 로그인 성공·실패·CSV 열람 등 보안 로그가 이미 있고, vuln 쪽도 이 로그를 거의 그대로 물려받았습니다. S2 가 A09 를 진단하려 해도 찾을 게 마땅치 않을 수 있습니다. **로그를 일부러 빼서 채울지, 아니면 이 항목은 범위에서 뺄지 팀 논의가 필요합니다.**
- **W2 비밀번호 재설정**은 여전히 코드에 없습니다. 전화 인증 가입으로 같은 성격(인증 절차 취약)은 채웠지만, PLAN.md 가 적은 그대로는 아닙니다. 이대로 둘지, "재설정" 기능을 새로 만들지 정해야 합니다.
- W7 의 구버전 라이브러리(A03)·HTTP 전송(A04) 쪽은 이번 점검에서 확인하지 못했습니다. 다음 점검 때 봐야 합니다.
