# 4개 역할 분담

## 역할

| 담당 | 주요 책임 | 주요 결과물 |
|---|---|---|
| 게임 기획 | 게임 흐름, 층별 목표와 퍼즐 규칙 설계 | 플레이 흐름, 시나리오, 증거와 힌트, 완료 조건 |
| 프런트엔드 | 게임 화면과 사용자 상호작용 구현 | 층 진행 화면, 가상 터미널 UI, 대화창, 선택지, 결과 화면 |
| 백엔드·보안 | Python 시뮬레이션 서버와 안전 경계 구현 | FastAPI 서버, 합성 데이터, 퍼즐 판정 API, 요청 검증 |
| LLM | AI 동료의 대화와 응답 품질 구현 | 프롬프트, 컨텍스트 구성, 신뢰도 규칙, 응답 스키마 검증 |

역할은 주 담당을 정하는 방식이며, 퍼즐 내용과 완료 조건은 담당자들이 함께 결정한다. 보안 검토와 테스트도 팀 전체의 책임으로 둔다.

각 담당자의 AI 도구에 붙여 넣어 사용할 네 역할의 프롬프트는 [role-prompts.md](./role-prompts.md)에 모아 두었다.
페이지 UI 구성용 메타프롬프트는 [page-ui-meta-prompt.md](./page-ui-meta-prompt.md)를 참고한다.
현재 소스 구조, 역할별 구현 경계, 독립 테스트 방법은 [project-structure.md](./project-structure.md)를 참고한다.

## 담당별 작업

### 게임 기획

- 첫 번째 층의 목표와 화면 흐름을 기획한다.

### 프런트엔드

- Next.js 화면, 가상 터미널, 대화 패널을 구현한다.
- 서버와 LLM 응답의 로딩·오류·재시도 상태를 표시한다.
- 게임 진행 상태와 저장 방식을 연결한다.

### 백엔드·보안

- FastAPI 기반의 가상 웹 시나리오를 구현한다.
- 합성 계정과 로그 등 게임 전용 데이터를 제공한다.
- 명시적으로 허용된 게임 행동만 처리하고, 임의 명령 실행은 지원하지 않는다.
- 공개 배포 시 외부 네트워크와 호스트 파일 접근을 제한하는 방안을 담당한다.

### LLM

- AI 동료의 성격, 말투, 불확실성 표현을 설계한다.
- 현재 층, 목표, 발견한 증거 등 필요한 게임 상태만 모델에 전달한다.
- 답변에 근거와 확신 수준을 포함하도록 구성한다.
- 모델 출력 형식을 검증하고, 형식이 맞지 않거나 실패한 응답을 안전하게 처리한다.
- 모델 API 키는 브라우저에 노출하지 않고 서버 측에서 관리한다.

## 먼저 합의할 데이터 인터페이스

```ts
type FloorState = {
  floor: number;
  objective: string;
  evidence: Evidence[];
  discoveredFlags: string[];
  llmTrust: number;
  completed: boolean;
};
```

퍼즐 상태의 최종 판정은 게임 엔진이나 백엔드가 맡고, LLM은 대화와 힌트를 제공한다. 모델 답변만으로 퍼즐을 완료 처리하지 않는다.

## 첫 MVP 목표

첫 스프린트에서는 탑의 한 층을 끝까지 플레이할 수 있는 수직 슬라이스를 만든다.

1. 게임 기획: 한 층의 목표, 증거, 힌트와 완료 조건 정의
2. 프런트엔드: 층 화면, 대화창, 가상 터미널, 성공·실패 흐름 구현
3. 백엔드·보안: 하나의 합성 시나리오와 퍼즐 판정 API 구현
4. LLM: 해당 시나리오의 AI 동료 응답과 검증 로직 구현
5. 공동: 정상 해결, 힌트 사용, 잘못된 입력, 서버·모델 오류를 함께 테스트

## 협업 규칙

- API와 상태 형식을 구현 전에 합의하고 함께 변경한다.
- 시나리오의 목표, 허용 행동, 정답 조건, 힌트를 한곳에서 관리한다.
- 매 스프린트 한 명을 통합 담당으로 정해 각자의 작업을 연결하고, 담당은 교대한다.
- 외부 사이트나 실제 사용자 데이터 대신 허가된 테스트 환경과 합성 데이터만 사용한다.
