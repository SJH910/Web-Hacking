제안 개요

「용범의 탑」을 실시간 브라우저 게임으로 만든다.
한 층의 관문을 통과할 때마다 데이터가 불완전한 AI 동료와 가상의 취약 웹 시스템을 조사한다.
실제 공격 기능이나 외부 공격 대상은 제공하지 않고, 격리된 로컬 실습 환경에서 제한된 퍼즐을 해결하는 것이 목표다.

팀 역할 분담은 [team-roles.md](./team-roles.md)를 참고한다.

핵심 컨셉

- 플레이어는 학습 데이터가 부족한 LLM 조력자와 대화한다.
- AI는 오답이나 근거 없는 주장을 섞어 내지만, 검증 가능한 힌트를 제공한다.
- 신의 탑처럼 층마다 선택과 장애물이 달라지는 던전 구조로 구성한다.
- 웹해킹은 가상의 브라우저, 터미널, 취약점 시나리오로 구현한다.
- 허용된 시뮬레이션 범위 밖의 명령이나 실제 네트워크 요청은 실행되지 않는다.

주요 게임 요소

1. 미완성 인공지능 파트너
   - 관계도와 신뢰도에 따라 도움의 정확도가 변한다.
   - 초기에는 규칙 기반 답변과 고정 시나리오를 사용한다.
   - 일부 답변에 오류를 넣어 플레이어가 로그와 증거로 검증하도록 만든다.

2. 탑 탐험
   - 10개 층을 기본 플레이 루트로 한다.
   - 각 층은 수사, 추론, 대화, 방어 중 하나의 관문 형식을 사용한다.
   - 선택에 따라 다음 층과 엔딩이 분기한다.

3. 안전한 웹해킹 퍼즐
   - 가상의 웹 페이지와 터미널에서 허용된 명령만 실행한다.
   - 로그 분석, 입력 검증 문제 찾기, 헤더 이상 설명, 권한 설정 점검 등을 배치한다.
   - 실험 환경은 로컬 전용 샌드박스이며 합성 계정과 가상 데이터만 사용한다.
   - 외부 도메인 접근, 임의의 셸 실행, 실제 서비스 계정 탈취 기능은 제외한다.

기본 화면 구성

- 상단: 현재 층, 남은 시간, 조력자 신뢰도
- 중앙: 가상 웹 화면 또는 터미널 인터페이스
- 우측: 대화형 LLM 패널과 증거 기록
- 하단: 행동 선택과 탐색 지도

권장 기술

- 프론트엔드: TypeScript와 React 또는 Svelte
- 웹 에뮬레이션: 명령어를 파싱하고 허용 목록을 검사하는 문제 엔진
- 데이터 저장: LocalStorage 또는 SQLite
- AI 구현: 초기에는 정적 시나리오와 규칙 기반 답변을 사용
- 선택적 확장: 고정 시드와 서버 프록시를 적용한 작은 생성 모델 API

개발 계획

1단계. 수직 슬라이스
   - 첫 번째 탑의 한 층을 구현한다.
   - 가상 터미널, 대화 패널, 선택지, 간단한 점수 시스템을 완성한다.

2단계. 게임 루프
   - 로그 수집과 사실 검증 체계를 구현한다.
   - 의심스러운 답변과 신뢰도 시스템을 추가한다.
   - 세이브, 로드, 분기 결과를 구현한다.

3단계. 콘텐츠 확장
   - 총 10개 층과 다중 엔딩을 제작한다.
   - 층별 소재와 난이도를 조정한다.
   - 튜토리얼과 실수 복구 흐름을 추가한다.

안전 및 교육 목표

- 실제 침투 도구나 자동 공격 코드 대신 방어적 사고와 안전한 실습을 중심으로 한다.
- 모든 취약점은 합성 시스템과 가상 데이터로만 재현한다.
- 사용자가 LLM의 주장과 자료를 출처와 근거로 검증하는 습관을 학습한다.

성공 기준

- 사용자가 10분 안에 첫 관문을 이해하고 해결할 수 있다.
- 관문마다 힌트와 검증 가능한 정답 근거가 있다.
- 실제 네트워크 또는 로컬 파일시스템으로 실행 범위를 벗어나지 않는다.
- 새 계정 또는 재시작 시 외부 설정 없이 바로 플레이할 수 있다.
