## 1. 결과 요약

vulnscan이 이미 저장한 소견 JSON(`owasp/title/severity/status/evidence/note`)을 게임의 `evidence`와 터미널 `commands`(출력)로 굽는다. 어떤 요청도 보내지 않는다(floor-slice-design §8의 "구워서 채움").

## 2. 상세

- [game_adapter.py](../../../tools/vulnscan/game_adapter.py): `bake(findings, max_items=3)` → `(evidence, commands, verdict)`.
  - `status`가 vuln·safe·manual인 소견만 앞에서 N개 사용(error 등 제외).
  - 소견마다 증거 `E1..`와 명령 `inspect e1..`(출력 = 제목·증거·메모)을 만든다.
  - 판정 힌트: vuln 포함 → 취약, manual 또는 소견 없음 → 증거 부족, 전부 safe → 양호.
  - 제어 문자 제거, 필드 길이 제한.
- 사용: `python tools/vulnscan/game_adapter.py <scan.json> [개수]` → JSON 출력을 새 문제 dict에 붙여 넣는다. 보기(3단 판정)와 힌트는 사람이 저작한다.
- 서버 런타임(`game_engine`)은 이 모듈을 import하지 않는다.

## 3. 검증

`test_game_adapter.py`: 더미 소견으로 구운 결과가 `parse_problem` 검증을 통과, 판정 규칙, 위험 문자·길이 정리. B4 안전 테스트(금지 import·호출)도 이 파일에 적용된다.
