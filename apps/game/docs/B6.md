## 1. 결과 요약

`POST runs/:id/ranking`(10층 통과 후 서버 점수로 등록, 등반당 1회)과 `GET rankings`(상위 100, 점수→신뢰도→힌트 적은 순)를 구현했다. 점수는 서버 계산값이라 조작할 수 없다.

## 2. 상세

- 마지막 층 통과 전·중복 등록은 409.
- 이름은 body `name`을 공백 정리 후 20자로 자르고, 없으면 `등반가-xxxx`.

## 3. 검증

`test_game_store.py`: 두 등반의 순위·rank 번호·중복 등록 거부.

## 4. 남은 것·참고

- **남은 것:** 이름·참가자 식별·등록 권한 정책 결정 후 반영. 여러 서버가 랭킹을 공유해야 하면 저장소 교체.

- 이름·참가자 식별·등록 권한 정책은 팀 결정 필요(FE-api-contract 마지막 항목). 현재는 인증 없음.
- 동점이면 먼저 등록한 쪽이 앞선다.
