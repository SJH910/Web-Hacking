## 1. 결과 요약

잘못된 입력은 400/404/409/413, 과다 요청은 429로 거부한다. 거부해도 상태·점수는 바뀌지 않는다.

## 2. 상세

| 항목 | 규칙 |
|---|---|
| 본문 | JSON 객체만, 8KB 초과 413, 파싱 실패 400 |
| requestId / revision | requestId는 영문·숫자·하이픈 8~64자, revision은 정수(아니면 400), 오래되면 409 |
| 명령 | 문자열 200자 이하(초과 400) |
| 증거·판정 | `evidenceIds`는 알려진 번호 목록, `choiceId`는 현재 단계의 보기 |
| 경로 | 조각 4개 초과·형식 위반 runId는 404 |
| 요청 제한 | 클라이언트(IP)당 10초 60회, 등반 생성은 분당 10회 → 429 |

## 3. 검증

`test_game_engine.py`의 `LimitTest`(제한·경계값 200/201자·잘못된 runId)와 `test_bad_input`.

## 4. 남은 것·참고

- 요청 제한은 프로세스 메모리 기준이다(`shortcut:` 다중 프로세스면 공유 저장소로 이전).
- FE는 non-2xx를 "상태 다시 불러오기"로 안내하므로 429도 별도 처리 없이 동작한다.
