## 1. 결과 요약

FE 제안 계약(FE-api-contract.md)의 `/api/game/*` 9개 엔드포인트를 구현했다. 명령 출력·완료 조건·3단 판정·점수·신뢰도·엔딩 6종·플래그를 모두 서버가 결정한다.

## 2. 상세

- [game_engine.py](../../../tools/vulnscan/game_engine.py): 점수·신뢰도는 scoring-trust.md(G4), 엔딩은 ending-branches.md(G7) 수치 그대로.
- [scanner.py](../../../tools/vulnscan/scanner.py): `/api/game/` 라우팅, 요청 본문 8KB 제한.
- 명령은 소문자·공백 정규화 후 **전체 일치(fullmatch)** 만 허용한다. 차단 입력은 정상 응답(`허용되지 않은 명령입니다.`)이며 상태·점수는 바뀌지 않는다.
- 같은 requestId는 이전 응답을 그대로 돌려주고(재처리 안 함), 오래된 revision은 409.
- 응답에 `correct`·`isTrap`·해설·플래그(통과 전)·명령 정의가 들어가지 않는다(테스트로 확인).

## 3. 검증

`test_game_engine.py`: 2층 전체 흐름·점수 계산·조사 전 판정 거부·힌트 감점/한도·409·중복 요청·정답 비노출. 실제 서버에 `curl`로 생성·명령·409·413 확인.

## 4. 남은 것·참고

- 랭킹 등록의 이름 정책은 미확정이라 body의 선택 필드 `name`(20자)을 받고, 없으면 임의 이름을 붙인다. 인증은 없고 runId가 사실상 열쇠다.
- 신뢰도 구간별 힌트 품질(clear/mixed/weak)은 L 담당이며 지금은 원문 힌트를 항상 `source:"rule"`로 준다.
- 최대 층 수는 출제된 문제 수(풀이 10 미만이면 그만큼)다.
