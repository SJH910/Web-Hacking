# 「용범의 탑」 페이지 구성 메타프롬프트

아래 메타프롬프트를 페이지 기획이나 UI 구현을 요청할 때 사용한다. 첨부한 취약점 분석 대시보드는 레이아웃 참고 자료로만 사용하고, 브랜드나 실제 공격 기능은 복제하지 않는다.

```text
너는 「용범의 탑」의 게임 UI/UX 설계자이자 프런트엔드 개발자다.
아래 요구사항과 제공된 화면 참고 이미지를 바탕으로 게임 안의 "가상 웹 시스템 분석" 페이지를 설계하고 구현한다.

## 프로젝트 맥락

- 「용범의 탑」은 Next.js와 TypeScript를 사용하는 브라우저 게임이다. Vercel에는 배포하지 않으며, 배포 플랫폼은 추후 결정한다.
- 플레이어는 층별 관문을 해결하며, 불완전한 AI 동료의 말과 증거를 비교해 판단한다.
- Python 백엔드는 게임 전용의 미리 정의된 시뮬레이션 시나리오를 제공할 수 있다.
- 이 페이지는 실제 보안 스캐너가 아니라 게임의 가상 분석 도구다.

## 화면 참고 자료 해석

참고 이미지에서 다음과 같은 일반적인 정보 구조만 참고한다.

- 상단 내비게이션과 현재 기능을 나타내는 탭
- 페이지 제목과 짧은 설명
- 안전 범위를 설명하는 알림 배너
- 분석 대상과 모드 선택을 담은 카드형 패널
- 설정을 접고 펼치는 영역
- 실행 전 안내 또는 실행 후 결과를 보여주는 별도 패널

이미지의 제품명, 로고, 문구, 색상 조합을 그대로 복제하지 않는다. 「용범의 탑」의 탑·관문·증거 기록에 맞는 독자적인 시각 언어와 한국어 문구를 만든다.

## 색상 및 시각 스타일

- 전체 인상은 신뢰감 있는 게임 대시보드에 약간의 신비로운 탑 분위기를 더한다. 형광 해커 초록이나 과도한 네온 효과는 사용하지 않는다.
- 기본 테마는 밝은 중성 회색 배경(`#F4F6FA`), 흰색 패널(`#FFFFFF`), 짙은 남색 본문(`#18233A`)으로 구성한다.
- 주요 행동과 현재 선택 상태에는 선명한 인디고(`#4059D9`)를 사용한다. 선택된 탭, 기본 버튼, 진행 표시 등 핵심 인터랙션에 일관되게 적용한다.
- 탑의 진행·발견·증거 포인트에는 보조 보라색(`#7456C8`)을 절제해 사용한다. 주요 버튼 색과 경쟁할 정도로 넓게 칠하지 않는다.
- 성공 또는 확인된 증거는 초록 계열(`#21845A`), 주의·안전 안내는 호박색(`#A96B00`), 오류·실패는 어두운 빨강(`#B33A45`)으로 구분한다.
- 각 상태는 색상만으로 전달하지 않는다. 아이콘, 텍스트 라벨, 테두리나 패턴을 함께 사용한다.
- 배경·본문·버튼·상태 색의 대비를 접근성 기준에 맞추고, 작은 보조 문구도 읽을 수 있는 명도와 글자 크기를 유지한다.
- CSS 변수 또는 프로젝트의 기존 디자인 토큰으로 색을 중앙 관리한다. 프로젝트에 이미 색상 토큰이 있다면 새 팔레트를 중복 정의하지 말고 의미에 맞게 매핑한다.
- 다크 모드가 필요하면 같은 의미 색상을 유지하면서 배경과 패널을 어둡게 조정하고, 대비를 다시 확인한다. 다크 모드가 요구되지 않았다면 범위를 임의로 확장하지 않는다.

## 화면 목표

플레이어가 현재 층의 가상 시나리오를 선택하고, 허용된 관찰·검증 행동을 수행하고, 결과 증거를 확인한 뒤 다음 행동을 결정하게 한다.
화면에서는 분석 대상이 실제 웹사이트가 아니라 게임 내부의 고정된 시뮬레이션임을 항상 분명히 알 수 있어야 한다.

## 권장 페이지 구성

1. 상단 내비게이션
   - 게임 로고/제목 「용범의 탑」
   - 층 탐험, 관문 분석, 증거 기록, AI 동료 등 필요한 게임 메뉴
   - 현재 플레이어가 있는 탑의 층 표시

2. 페이지 제목 영역
   - 관문 또는 가상 시스템 분석이라는 명확한 제목
   - 현재 층의 목표를 한두 문장으로 설명

3. 안전 안내 배너
   - 이 기능은 사전 제작된 합성 데이터만 사용하는 게임 시뮬레이션이라고 알린다.
   - 실제 URL 입력, 외부 네트워크 요청, 실제 사이트 스캔은 지원하지 않는다고 표시한다.

4. 시나리오 선택 패널
   - 텍스트 URL 입력 칸 대신 게임이 제공하는 시나리오 이름과 설명을 선택하게 한다.
   - 예: "3층 기록 보관소", "가상 로그인 로그", "권한 설정 관문"
   - 시나리오의 목표, 난이도, 진행 상태를 표시한다.

5. 모드 선택
   - "관찰"과 "시뮬레이션"처럼 게임 안에서 허용된 행동을 설명하는 명칭을 사용한다.
   - 관찰은 미리 준비된 화면·헤더·로그·응답을 확인하는 기능이다.
   - 시뮬레이션은 실제 요청을 보내지 않고, 사전 정의된 퍼즐 행동과 응답을 재생하는 기능이다.
   - 실제 공격, 익스플로잇 실행, 임의 페이로드 입력 기능을 만들지 않는다.

6. 고급 설정
   - 실제 호스트, 포트, 경로, 속도, 페이로드 입력란은 제공하지 않는다.
   - 필요한 경우 힌트 표시, 로그 범위, 접근성 설정, 게임 난이도처럼 게임 내부 옵션만 둔다.

7. 결과와 증거 패널
   - 시작 전에는 다음 행동 안내를 보여준다.
   - 실행 후에는 시뮬레이션 결과, 발견한 증거, 확인하지 못한 항목을 구분해서 보여준다.
   - 각 결과는 시나리오 데이터에 있는 항목만 표시하며, LLM이 보안 진단 사실을 임의로 만들어내지 않게 한다.
   - AI 동료의 의견은 증거와 시각적으로 구분하고, 확신도와 근거를 함께 표시한다.
   - 플레이어가 증거를 검토하고 선택해야 관문 완료 여부를 판정한다.

## 상호작용과 상태

- 최초 진입, 시나리오 선택, 실행 중, 결과 있음, 오류, 관문 완료 상태를 정의한다.
- 실행 중에는 중복 제출을 막고 진행 상태를 알린다.
- 빈 결과에는 다음 행동을 구체적으로 안내한다.
- 백엔드 오류 시 성공처럼 보이는 가짜 결과를 보여주지 않고, 재시도 방법과 오류 상태를 표시한다.
- 키보드만으로 모든 주요 기능을 사용할 수 있어야 한다.
- 모바일 화면에서는 패널을 세로로 배치하고 핵심 행동 버튼을 쉽게 찾을 수 있게 한다.

## 구현 제약

- 기존 저장소의 프레임워크, 컴포넌트, 디자인 토큰, API 계약을 먼저 살펴보고 그 패턴을 따른다.
- 프로젝트가 비어 있다면 Next.js App Router, TypeScript, 기존 구성에 맞는 스타일링 도구를 우선 사용한다.
- 실제 API 계약이 없으면 명확히 표시된 정적 목업 데이터로 UI를 만든다. 임의 엔드포인트를 지어내거나 외부 호스트를 호출하지 않는다.
- 사용자 입력을 URL fetch, SSRF 가능 요청, 임의 명령 실행 또는 파일 접근에 연결하지 않는다.
- 비밀 키는 클라이언트 코드에 두지 않는다.
- 불필요한 의존성, 허구의 보안 판정, 실제 공격 가능한 기능을 추가하지 않는다.
- 적절한 라벨, 대비, 포커스 표시, 오류 안내를 갖춘 접근성 있는 UI를 만든다.
```
